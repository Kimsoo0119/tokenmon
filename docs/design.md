# tokenmon 설계 문서

Claude Code / Codex 주간 한도 소진율에 따라 진화하는 macOS 데스크탑 펫의 설계 배경을 정리한 문서입니다. 최초 설계는 2026-07-24에 작성했고, 이후 구현하며 달라진 부분을 반영해 갱신했습니다.

## 개요

macOS 데스크탑에 포켓몬 스프라이트를 띄우고, Claude Code 또는 Codex의 주간 한도 소진율에 따라 펫이 진화합니다. 주간 한도가 리셋되면 펫도 1단계로 돌아옵니다. 매주 새로 키우는 주기입니다.

## 확정 사항

| 항목 | 결정 |
|---|---|
| 진화 기준 | 주간 한도 소진율 % (Claude `seven_day.utilization` / Codex `secondary.used_percent`) |
| 스택 | Electron (투명 프레임리스 BrowserWindow) |
| 소스↔펫 | 펫 1마리, 설정에서 Claude/Codex 중 소스 선택 |
| 모션 | GIF 재생 (`<img>` 네이티브 재생, 애니메이션 코드 없음) |
| 몬스터 추가 | 한글 이름 입력 → 자동 다운로드 + PokeAPI 진화체인 자동 인식. 커스텀은 로컬 GIF 지정 |
| 플랫폼 | macOS 전용 |

## 아키텍처

Electron 앱 하나로, 메인 프로세스와 렌더러 창 네 개로 구성됩니다.

**메인 프로세스** (`src/main.js`)

- 트레이 아이콘: 현재 펫 스프라이트 + `Lv.{주간 소진율}` 표시. 조회에 실패하면 `⚠️`
- 펫 · 패널 · 말풍선 · 도감 창의 생명주기 관리
- 몬스터 등록과 도감 기록을 도맡습니다 (아래 *도감* 참고)
- 5분 간격 사용량 폴링 후 각 창에 IPC로 전달 (`pollIntervalMin`으로 조정)
- 설정 저장: `app.getPath('userData')/config.json`
- `events.jsonl` 감시 (아래 *외부 알림 연동* 참고)

**펫 창** (`src/pet/`) — 투명 · 프레임리스 · 항상 최상위

- `<img>`로 현재 단계 GIF 재생
- 드래그로 위치 이동, 위치는 config에 저장
- 클릭하면 CSS 공격 모션과 함께 사용량 말풍선 표시
- 진화하는 순간에는 플래시 이펙트 후 다음 단계 GIF로 교체
- 몬스터가 없으면 알 이미지를 흔들며 띄우고, 클릭하면 설정이 열립니다 (첫 실행 온보딩)
- 스프라이트 바깥의 투명한 여백은 클릭이 아래 창으로 통과합니다

**패널 창** (`src/panel/`) — 트레이를 누르면 열리는 사용량 카드

- 5시간 / 주간 사용량 게이지와 다음 진화까지 남은 수치
- 설정도 이 안에 접이식 섹션으로 들어 있습니다. 별도의 설정 창은 두지 않습니다
- 카드 실제 높이에 맞춰 창 크기가 따라갑니다. 고정 높이로 두면 투명 창 주변에 OS 그림자가 남습니다

**말풍선 창** (`src/pet/bubble.html`) — 독립된 투명 창

펫 창 안에 말풍선을 그리면 펫 창 크기에 갇혀 잘리기 때문에 별도 창으로 분리했습니다. 펫 위치를 기준으로 위아래를 자동으로 정하고, 화면 밖으로 나가지 않도록 좌표를 직접 보정한 뒤 꼬리 위치만 따로 옮깁니다.

**도감 창** (`src/dex/`) — 트레이 메뉴나 패널 버튼으로 여는 브라우징 창

다른 세 창과 달리 항상 최상위가 아니고, 크기를 바꿀 수 있으며, 불투명합니다. 649칸을 스크롤하며 보는 화면이라 패널 안에 넣을 수 없습니다 — 패널은 트레이 아래 남은 높이에 맞춰 스스로 크기를 조절하는데 거기에 그리드를 얹으면 그 조절이 무너집니다.

독 아이콘을 숨긴 앱이라 창을 띄우는 것만으로는 키보드 초점이 오지 않습니다. `app.focus({ steal: true })`를 함께 부르지 않으면 도감은 떠도 검색창에 글자가 들어가지 않습니다.

## 데이터 소스

| 소스 | 방법 | 주간 % 필드 |
|---|---|---|
| Claude | macOS Keychain `Claude Code-credentials` → accessToken → `GET https://api.anthropic.com/api/oauth/usage` (`anthropic-beta: oauth-2025-04-20`) | `seven_day.utilization` |
| Codex | `~/.codex/sessions/**/*.jsonl` 중 수정 시각이 최근인 50개를 스캔 | `rate_limits.secondary.used_percent` (window_minutes=10080) |

에러 처리:

- **429 응답**: usage 엔드포인트에는 호출 제한이 있습니다. 2026년 7월에 실측해보니 **5분 남짓한 창에 4회까지 통과하고 5회째부터 429**가 나오며, `retry-after`로 300초를 줍니다. 응답에 `anthropic-ratelimit-*` 헤더가 없어 남은 횟수를 미리 알 방법은 없습니다. 429를 받으면 `retry-after`만큼(헤더가 없으면 300초) 조회를 멈추고 여유분 30초를 더해 재시도하며, 그동안에는 마지막 값을 그대로 보여줍니다.

  참고로 [공개 API 문서의 rate limit](https://platform.claude.com/docs/en/api/rate-limits)은 Messages API 기준이라 이 엔드포인트에는 적용되지 않습니다.

  기본값인 5분 주기는 이 한계에서 충분히 여유가 있어 429를 맞지 않습니다. 주기를 줄이더라도 2분 아래로는 내리지 않는 편이 좋습니다. 1분으로 잡으면 5분에 5회를 호출해 한계선에 걸리기 때문에 주기적으로 429를 맞고, 그때마다 5분 넘게 값이 멈춰 오히려 갱신이 느려집니다. Codex는 로컬 파일만 읽기 때문에 이 제한과 무관합니다.
- **토큰 만료 · 네트워크 실패**: 마지막 성공 값을 계속 표시하고 트레이에 경고를 띄웁니다. 이 값은 config에 저장해두어 앱을 다시 켰을 때도 곧바로 보여줍니다.
- **Codex 로그에 rate_limits가 없는 세션**: 더 이전 파일로 넘어갑니다.
- **주간 리셋**: 소진율이 떨어지면 단계도 자연히 내려갑니다. 진화 로직이 현재 % 기준으로 매번 다시 계산하기 때문에 따로 처리할 것이 없습니다.

## 진화 로직

```jsonc
// config.json 핵심 스키마
{
  "source": "claude",            // "claude" | "codex"
  "pollIntervalMin": 5,
  "petSize": 140,
  "usageCache": {},              // 소스별 마지막 성공 조회값 { usage, at }
  "petPosition": { "x": 0, "y": 0 },
  "activeMonster": "pichu-pikachu-raichu",
  "activePickedResetAt": 1786194000312,  // 이 시각이 지나야 다른 계통을 고를 수 있다
  "monsters": {
    "pichu-pikachu-raichu": {    // id = 슬러그를 '-'로 이은 값
      "displayName": "라이츄",
      "stages": [
        { "name": "피츄",   "slug": "pichu",   "gif": "cache/pichu.gif" },
        { "name": "피카츄", "slug": "pikachu", "gif": "cache/pikachu.gif" },
        { "name": "라이츄", "slug": "raichu",  "gif": "cache/raichu.gif" }
      ],
      "thresholds": [33, 67]     // 길이 = stages.length - 1
    }
  },
  "dex": {                       // 도감 기록. 슬러그 → 처음 만난 시각
    "seen":   { "pichu": 1785889410081 },
    "caught": { "pichu": 1785889410081 }
  },
  "dexEnabled": false,           // 꺼져 있으면 아무 때나 포켓몬을 고를 수 있다
  "dexFreeMode": false,          // 규칙 없이 둘러보기 (전 종 공개 + 주간 제한 해제)
  "dexOnboarded": false          // 도감 안내를 끝까지 봤는지
}
```

단계마다 `slug`를 따로 담는 이유는 id에서 되돌릴 수 없기 때문입니다. id는 슬러그를 `-`로 이은 값인데 `mr-mime`이나 `jangmo-o`처럼 슬러그 자체에 하이픈이 있는 종이 있어, `mime-jr-mr-mime`을 어디서 끊어야 할지 알 방법이 없습니다. `slug`가 없던 시절의 설정은 읽을 때 스프라이트 파일 이름에서 되살립니다.

설정 화면은 창을 열 때 읽어둔 설정을 통째로 덮어쓰기 때문에, 메인만 쓰는 필드(`petPosition` · `usageCache` · `dex` · `activePickedResetAt` · `dexEnabled` · `dexFreeMode` · `dexOnboarded`)는 저장 직전에 파일에서 다시 읽어 되돌립니다.

- 현재 단계는 thresholds 중 현재 % 이상인 마지막 인덱스에 1을 더한 값입니다 (0-기반)
- 기본은 3단계입니다. 단계를 추가하거나 지우면 임계값을 균등분할로 다시 잡고, 이후 수동으로 고칠 수 있습니다
- 임계값은 오름차순이면서 0에서 100 사이여야 합니다

## 몬스터 추가

설정에서 이름을 입력하거나, 도감에서 칸을 눌러 추가합니다.

1. 한글 이름을 `assets/names-ko.json`으로 영문 슬러그로 바꿉니다. 이 파일은 PokeAPI species 전체(1025종)에서 만든 한글→영문 매핑이라, 도감에 없는 종을 입력해도 무엇을 찾았는지 알 수 있습니다. 변환에 실패하면 입력값을 영문 슬러그로 봅니다
2. `assets/dex.json`에서 계보를 꺼내 한글 이름으로 보여줍니다 (피츄 → 피카츄 → 라이츄). 네트워크를 쓰지 않습니다
3. 분기 진화(이브이 등)는 첫 번째 분기를 기본으로 고르고 드롭다운으로 바꿉니다
4. 각 단계 GIF를 `https://img.pokemondb.net/sprites/black-white/anim/normal/{slug}.gif`에서 받아 `userData/cache/`에 저장합니다
5. 커스텀 몬스터는 단계별로 로컬 GIF를 직접 지정하고 이름도 자유롭게 적습니다

**추가한 계통이 곧바로 활성 몬스터가 됩니다.** 고르고 나서 화면이 그대로면 고른 보람이 없기 때문입니다. 이미 있던 계통을 다시 고르면 손봐둔 임계값은 그대로 둡니다.

**한 주에 한 마리만 고를 수 있습니다.** 고른 시점의 주간 리셋 시각을 `activePickedResetAt`에 적어두고, 그 시각이 지나 새 주가 시작되기 전에는 다른 계통으로 바꿀 수 없습니다. 아무 때나 갈아탈 수 있으면 한 마리를 끝까지 키운다는 말이 무색해지기 때문입니다. 이전 몬스터는 목록에 남아 있어 다음 주에 다시 고를 수 있습니다.

잠긴 상태인지는 **고를 때 적어둔 리셋 시각이 아직 오지 않았는지**로 봅니다. 지금 조회값과 같은지로 보면 안 됩니다 — usage API가 같은 리셋을 가리키면서도 매번 1초 안팎으로 다른 값을 주기 때문에, 폴링이 한 번만 돌아도 잠금이 저절로 풀립니다. 실제로 그렇게 만들었다가 겪은 일이라 `pickLock`을 순수 함수로 떼어 회귀 테스트를 붙여두었습니다.

판정은 메인이 하고 화면은 받아 씁니다. 활성 몬스터 변경을 `set-active-monster` IPC로 옮긴 것도 같은 이유입니다 — 렌더러가 설정을 직접 고치면 잠금을 우회합니다. 소진율을 아직 모를 때는 막지 않습니다. 조회에 실패했다고 갇히면 곤란하기 때문입니다.

**도감을 쓰는 동안에는 고르는 창구가 도감 하나뿐입니다.** 설정의 «포켓몬 추가»와 «커스텀 몬스터»를 감추고 몬스터 목록의 라디오도 빼서, 도감을 열어 고르는 버튼만 남깁니다. 두 창구를 함께 열어두면 도감을 거치지 않고 규칙을 지나가게 됩니다. 임계값 편집과 삭제는 고르는 것과 다른 일이라 그대로 둡니다. 도감을 끄면 예전 화면이 그대로 돌아옵니다.

등록은 패널과 도감 어느 쪽에서 시작하든 메인 프로세스의 `add-monster` 하나를 거칩니다. 창마다 등록 코드를 두면 두 벌이 어긋나기 시작하고, 설정 화면의 코드는 패널 창 전역에 있어 다른 창에서 가져다 쓸 수도 없습니다. GIF를 모두 받은 뒤에야 설정을 건드리므로 도중에 실패해도 반쯤 만들어진 몬스터가 남지 않습니다.

스프라이트는 저장소에 포함하지 않고 실행 중에만 내려받습니다.

## 도감

`assets/dex.json`에 실린 종을 세대 탭으로 나눠 보여주고, 아직 키워보지 않은 종은 실루엣으로 남겨둡니다.

**기본은 꺼져 있습니다.** 도감을 켜면 «한 주에 한 마리»라는 제약이 따라오는데, 그건 모르고 받을 제약이 아닙니다. 그래서 도감 버튼은 늘 보이되 꺼진 상태에서 누르면 무엇이 달라지는지 알리고 동의를 받습니다. 꺼져 있는 동안에는 예전처럼 아무 때나 포켓몬을 고를 수 있습니다.

확인 대화상자는 메인 프로세스의 `dialog.showMessageBox`로 띄웁니다. 렌더러의 `confirm`은 패널을 blur시켜 패널이 닫혀버립니다.

**«규칙 없이 둘러보기»는 전 종을 공개하고 주간 1회 제한도 풉니다.** 도감을 수집물이 아니라 도감 그 자체로 보고 싶을 때를 위한 설정입니다. 화면에서만 드러낼 뿐 `dex.caught` 기록은 건드리지 않으므로, 다시 끄면 진짜 진행도가 그대로 돌아옵니다. 나중에 붙일 전설 해금 조건도 이 설정이 켜져 있으면 적용하지 않습니다.

**처음 켜면 안내를 한 번 보여줍니다** (`dexOnboarded`). 실루엣·`●`/`▲` 배지·주간 1회는 화면만 봐서는 알기 어려운 규칙이라 도감 창 위에 세 장짜리 오버레이로 짚어줍니다. 첫 장은 말로 풀지 않고 컬러 칸과 실루엣 칸을 나란히 보여줍니다.

**수록 범위는 649종입니다.** 펫으로 쓰는 흑백 애니메이션 스프라이트가 5세대 게임의 도트라 그 시점까지의 종만 존재합니다 (`genesect` 649는 있고 `chespin` 650은 없습니다). 6세대 이후를 도감에 실으면 눌러도 등록되지 않는 칸이 376개 생기므로, 등록할 수 있는 종만 싣습니다. 넓히려면 `scripts/build-dex.js`의 `BW_ANIM_MAX_NO`와 스프라이트 출처를 함께 손봐야 합니다.

**칸이 열리는 기준은 도달입니다.** 실제로 그 단계까지 키워본 종만 원래 색과 이름을 드러내고, 나머지는 전부 검은 실루엣에 이름은 `???`입니다. 계통을 등록해두었을 뿐 아직 닿지 못한 종도 마찬가지입니다 — 도감에 색이 켜지는 것은 도달했다는 뜻이어야 하기 때문입니다. 주간 소진율이 리셋돼 단계가 내려가도 도달 기록은 지우지 않습니다.

가리는 규칙은 격자와 상세 시트가 같습니다. 한쪽에서만 가리면 눌러보는 것만으로 알아낼 수 있어 가리는 의미가 없어지므로, 시트의 큰 이름·스프라이트·진화 경로도 도달한 종만 드러냅니다 (`미뇽 → 신뇽 → ???`). 도감 번호와 세대는 격자에서도 보이는 값이라 그대로 두고, 전설·환상 여부처럼 키워봐야 알 수 있는 것은 도달 전까지 밝히지 않습니다.

`dex.seen`(계통을 등록한 적 있는 종)은 지금 화면에 쓰지 않습니다. 등록 이력 자체는 몬스터를 지워도 남길 값이라 기록만 해둡니다.

**칸은 개별 종인데 등록은 계통 단위**라 이 둘이 어긋납니다. 그래서 칸마다 여기서 시작할 수 있는 종인지(`●`) 진화로만 만나는 종인지(`▲`) 표시하고, 진화형을 눌렀을 때도 그 종을 지나는 계통만 추려 그 자리에서 등록까지 이어지게 합니다.

**진화 관계는 부모 링크(`from`)로만 표현합니다.** PokeAPI의 진화 체인 번호는 쓰지 않는데, 마나피와 피오네를 한 체인으로 묶어두기 때문입니다. 둘은 진화 관계가 아니라 알에서 나오는 사이라, 체인 번호로 종을 묶으면 하나를 등록했을 때 다른 하나까지 공개됩니다.

**기록은 메인 프로세스만 씁니다.** 렌더러가 각자 남기면 설정을 저장할 때마다 서로의 기록을 덮습니다. '알게 된 종'은 등록된 몬스터들의 계통을 합집합으로 다시 계산하므로 몬스터를 지워도 기록이 남습니다.

**'도달한 종'에는 시작선(floor)이 있습니다.** 소진율은 계정 전체의 값이라 몬스터마다 키운 정도가 따로 없습니다. 그대로 두면 새 몬스터를 고르는 순간 지금 소진율을 물려받아, 손도 대지 않은 진화형까지 도달한 것이 됩니다 — 50%에서 파이리를 추가하면 파이리와 리자드가 한꺼번에 도감에 들어갑니다. 그래서 활성으로 만든 시점의 단계를 시작선으로 잡고 **그보다 위로 올라간 것만** 인정합니다. 0단계에서 시작했다면 물려받은 것이 없으므로 그 모습부터 인정합니다.

주간 리셋으로 시작선보다 낮은 단계까지 내려오면 시작선도 함께 내려갑니다. 그래서 중간에 데려온 몬스터도 리셋을 한 번 지나면 아래 단계부터 차례로 채워집니다. 시작선은 설정에 남기지 않습니다 — 앱을 껐다 켜면 지금 단계를 물려받은 것으로 보는 편이 안전하고, 이미 남은 기록은 그대로이며 새로 공짜로 얻는 것만 막히기 때문입니다.

시작선 위로 올라갈 때는 중간 단계를 함께 찍습니다. 폴링이 5분 간격이라 그 사이 10%에서 80%로 뛰면 중간 단계를 못 보고 지나치는데, 그러면 라이츄는 도달했는데 피카츄는 못 만난 도감이 됩니다.

직접 고른 GIF로 만든 커스텀 몬스터는 도감에 실린 종이 아니므로 기록에 남지 않습니다.

**성능** — 세대 탭으로 나누면 한 번에 그리는 칸이 156개(5세대)를 넘지 않아 가상 스크롤이 필요 없습니다. 여기에 브라우저가 주는 `loading="lazy"`를 얹으면 처음 요청하는 그림은 화면에 보이는 30여 장뿐이고, 창의 디스크 캐시가 받아둔 그림을 남겨 두 번째 실행부터는 요청이 나가지 않습니다.

**데이터 만들기** — `node scripts/build-dex.js`는 PokeAPI GraphQL에 요청 한 번을 보내 1025종을 받아 649종으로 추린 뒤 `assets/dex.json`을 씁니다. REST로 종을 하나씩 받으면 요청이 천 번을 넘습니다. `--verify`를 붙이면 전 종의 스프라이트가 실제로 있는지 HEAD로 확인합니다. 결과물은 저장소에 커밋하므로 앱을 쓰는 쪽에서는 PokeAPI를 부르지 않습니다.

## 외부 알림 연동

`userData/events.jsonl`에 `{"message":"..."}` 한 줄이 추가되면 펫이 점프하며 말풍선으로 알립니다. 메인 프로세스가 `fs.watch`로 파일을 감시하다가 새로 늘어난 줄만 읽어 펫 창에 전달합니다. Claude Code의 Notification 훅과 연결하는 방법은 [README](../README.md)에 적어두었습니다.

알림 메시지는 외부에서 들어온 문자열이므로 DOM에 넣기 전에 반드시 이스케이프합니다.

## 보안상의 선택

렌더러는 `nodeIntegration: true`, `contextIsolation: false`로 둡니다. 외부 콘텐츠를 전혀 띄우지 않는 로컬 전용 앱이라 preload 다리를 놓는 비용이 이득보다 크다고 판단했습니다. 대신 외부에서 들어오는 문자열(알림 메시지, 사용자가 입력한 몬스터 이름, 슬러그)은 이스케이프와 검증을 거칩니다. 이스케이프 함수는 `src/esc.js` 한 곳에 둡니다 — 창마다 따로 두면 한 곳만 빠뜨려도 티가 나지 않습니다.

도감 창은 고정된 한 곳(`img.pokemondb.net`)의 그림만 원격으로 불러옵니다. 원격 HTML이나 스크립트는 어느 창에서도 불러오지 않습니다.

등록 요청은 IPC로 들어오므로 슬러그가 도감에 실린 것인지 먼저 확인합니다. 이름이 그대로 캐시 파일 경로가 되기 때문에, 이 검사와 `downloadGif`의 슬러그 검증이 경로를 벗어나는 값을 막는 두 겹입니다.

## 테스트

진화 로직(% → 단계 계산, 리셋 회귀, 임계값 검증), Codex JSONL 파서, config 병합과 마이그레이션, 도감 계보 계산, 몬스터 조립, 슬러그 검증, 이스케이프를 순수 함수로 떼어내 `node:test`로 검증합니다. Electron이나 네트워크에 기대지 않아 CI에서 Electron 바이너리 없이 돕니다.

`assets/dex.json`은 실물을 그대로 읽어 검사합니다 — 649종인지, 모든 부모가 도감 안에 있는지, 마나피와 피오네가 서로 다른 계통인지. 빌드 스크립트가 지켜야 할 약속이 파일에 살아 있는지 보는 자리입니다.

창 · 트레이 · GIF 재생 · 도감 화면은 수동으로 확인합니다.
